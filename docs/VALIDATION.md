## Foreground session recovery follow-up

- Repeated Home/return checks on 0.1.1 exposed a stopped native session while the visible UI reported **Network live** with **NO SIGNAL** and blank readings. The phone was unlocked, and the existing bridge process remained running. Source review found an unguarded state update after a callback's earlier generation check: that update could cross disconnect and prevent the new Surface from starting capture. This is an identified race path consistent with the failure, rather than a traced scheduling proof for that occurrence.
- Session-dependent state updates now check generation/start/closed state inside the MutableStateFlow CAS update. USB open, network callbacks/errors, fixture completion, saved-source completion and command results use that guard. Pending command state uses an atomic session token so an old command cannot clear a newer session's token. Explicitly reopening a saved file clears its prior resume cache before restoration.
