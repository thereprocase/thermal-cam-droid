# Thermal Field 0.1.3-rc1

Experimental Android release candidate for supported USB thermal hardware. Android 16/API 36 or newer; arm64 only. Independent branding, MIT project license and bundled dependency notices. No proprietary camera SDK. No GPS, device serial or source URL in captures.

Changes since 0.1.2:

- Image-first workspace with grouped controls, overlaid scale, useful letterbox controls and full screen.
- Four-way sensor-driven full-screen GUI rotation with lock; phone-mounted USB rendering/capture orientation compensation. Physical mounting checks remain open.
- Lossless capture/share, saved/live profile isolation, persistent measurement layouts and explicit stale-source/configuration capture guards.
- Band-integrated graybody correction, signed temperature inputs, mode-specific isotherms and readable scaled annotations with AVG labels.
- Saved USB gain recovery with all six startup readbacks checked; explicit gain controls and session-specific NUC command feedback.
- Separate gallery/capture workers, capture publication/cleanup checks and stream recovery controls.

Validation is scoped in docs/VALIDATION.md. Sixteen JVM tests, four host native suites and Pixel/AVD integration checks passed. Dense synthetic annotations were inspected in settled portrait/landscape layouts at 1.5× text scale. Three short direct-USB logical opens checked high/low/high startup, both gain directions, capture metadata, NUC command completion and USB descriptor counts returning to zero. Retained samples were about 25 fps with zero malformed/overflow/source-gap counts; callback-to-swap samples 3.49–4.11 ms. These ImageReader samples do not establish visible compositor latency or sustained maximum-workload qualification.

Open acceptance gates: one-minute maximum-workload direct USB, controlled physical detach/reattach, physical mounting/orientation and visible shutter freeze, actual share-target recovery, official-app parameter persistence/neutral baseline and ε=0.96 ice/~55 °C bath comparisons. An extended USB attempt failed at startup with IO error; the retry found no matching camera. Neither attempt is a passing workload result. Values are camera-apparent or model-corrected estimates under documented assumptions, not independently validated surface temperatures.

The APK, complete corresponding source archive and SHA256SUMS are supplied together. Update using this release signer; existing debug-signed installations use a different signer. Preserve captures/app data when choosing an installation path. Hosted CI is not claimed active.
